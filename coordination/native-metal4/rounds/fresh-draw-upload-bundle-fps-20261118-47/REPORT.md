# 네 경로 fresh draw upload 묶음

**OFF 63.93 FPS → ON 63.95 FPS (+0.02%).** 차이는 +0.015 FPS로, 이번 한 쌍에서 평균 성능 개선을 확인할 만한 크기는 아니었습니다.

| 지표 | 묶음 OFF | 묶음 ON |
|---|---:|---:|
| 1% low | 54.62 FPS | 55.44 FPS |
| 중앙값 / p95 / p99 | 16 / 17 / 18 ms | 16 / 17 / 18 ms |
| 최대 프레임 타임 | 26ms | 19ms |

| 포함 경로 | 슬롯 | 할당 변화 | 실제 첫 인코딩 |
|---|---|---:|---|
| 레이더·소나 센서 원 | 2·3·5 | 3→1 | 양쪽 확인, tick 0 |
| forward MapEdge | 0·1 | 2→1 | 미확인 |
| Blueprint 모델 | 1·2 | 2→1 | 양쪽 확인, tick −1 |
| Blockout 모델 | 1·2 | 2→1 | 미확인 |

확인된 두 첫 드로우의 시점은 측정 구간 전입니다. 이 시험의 FPS는 실제 장면의 묶음 ON/OFF 비교이며, 경로마다 발생 횟수와 개별 기여는 집계하지 않았습니다. MapEdge/Blockout의 실제 사용은 이번 로그로 확인되지 않습니다.

새 공용 헤더 1개와 실제 소비자 4개 파일에 적용했습니다. 정렬, 용량, 범위와 overflow 경계 6개를 정적으로 검증하고, 컴파일된 네 객체의 실제 링크 및 공용 헤더 의존성을 확인했습니다. 슬라이스는 그대로 복사한 입력으로 채워 GPU 완료까지 기존 lease에 소유·등록됩니다. 좁은 fresh 업로드만 대상으로 하고 기존 위치·index offset, mesh/snapshot, 텍스처·셰이더·draw 순서는 유지했습니다. 실패 조건마다 기존 개별 할당 경로를 사용하며 런타임에서 강제로 실패시키지는 않았습니다.

하나의 바이너리로 각 한 번, 같은 해상도·AA OFF·전투 시드·tick 540–1740에서 모든 프레임을 포함했습니다. 기존 통합 인덱싱은 양쪽 ON, SensorLOS slab와 GroundFlash는 양쪽 OFF였습니다. 두 게임 모두 정상 종료했고 원본/기존 후보 해시를 확인했습니다.

제출 단위의 슬라이스 발상은 Patrice Déry(PowerBeef)의 D2R Metal 포팅을 참고했고, 구현은 BAR의 기존 소유권 구조에 맞췄습니다. [고정 원문](https://github.com/PowerBeef/d2r-metal/blob/602db5fc30d4ce50683435cb0745cb171fce2064/dm/gfx/nvn/nvn_mtl.m#L3948-L3959)
