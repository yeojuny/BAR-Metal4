# SUPER JINI MK2 ↔ HQ 교신

이 폴더는 인계 상태를 공유하는 곳입니다. 실제 지니 수신 확인, 로컬 연결,
알림 연결은 아직 없으며 폴더만으로 자동화되거나 실행이 시작되지 않습니다.
초기 상태는 `WAITING_FOR_JINI_ACK`, `enabled: false`입니다.

- **SUPER JINI MK2**: 가설·소스 수정·결과 판단.
- **HQ**: 전달받은 고정 소스의 빌드·검증·벤치마크·증거 기록. 엔진 수정은 하지 않습니다.

## 인계 규칙

1. `coord/native-metal4` branch의 이 폴더에 있는 **STATE.json 한 파일**을 기준으로 합니다.
   GitHub 읽기 ref와 쓰기 branch를 명시하고, main으로 대신 읽거나 쓰지 않습니다.
2. JINI는 소스 수정과 하위 작업을 모두 끝낸 뒤 round ID, 고정 source commit(40 hex),
   source manifest SHA256(64 hex), 요청과 READY 경로를 기록하고 HQ에 넘깁니다.
3. HQ가 맡으면 JINI는 로컬 작업을 중지합니다. 측정 중에는 HQ 실행자 외 다른 로컬
   도구·읽기·UI 작업도 중지합니다. HQ는 고정 소스를 확인하고 요청 범위만 수행합니다.
4. GPU 작업·소유 프로세스·helper·awake 유지·worker·증거 쓰기를 정리한 뒤,
   같은 round/source에 결과 경로를 기록하고 DONE으로 돌려줍니다.
   빌드나 검증 실패도 원인과 로그를 반환하며, DONE은 성능 개선을 뜻하지 않습니다.
5. JINI가 결과를 읽고 판단을 기록한 뒤 다음 소스 수정으로 돌아갑니다.
   다음 인계는 새 round ID를 사용하고 이전 결과 경로는 history에 남깁니다.

STATE를 갱신할 때 최신 contents blob SHA를 expected `sha`로 사용하고 revision을 1 올립니다.
성공 후 다시 읽어 같은 내용인지 확인한 뒤 인계를 유효하게 봅니다.
알림 자체는 실행권이 아닙니다. 중복 알림으로 같은 round를 재실행하지 않습니다.
실행 이력이 불명확하거나 정리가 끝나지 않았으면 현재 소유자가 BLOCKED로 기록하고 멈춥니다.
응답 유실은 원격 상태와 실행 기록을 대조하며, 시간 초과만으로 소유권을 넘기지 않습니다.
main·릴리스·Homebrew 갱신 권한은 이 교신과 별개입니다.

양쪽 수신 확인은 각 당사자가 실제로 읽은 뒤에만 바꿉니다.
수신·로컬 연결·알림 경로를 확인하기 전에는 enabled를 true로 바꾸거나 실험을 시작하지 않습니다.
이 Draft PR은 교신 branch를 공유하기 위한 것이며 지금 main에 병합하지 않습니다.
