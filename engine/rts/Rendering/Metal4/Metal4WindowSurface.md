# Engine-owned direct SDL3 Metal surface

2026-10-14. Codex assisted this isolated source implementation. No real window, drawable acquisition, GPU submission or presentation was run by this owner. This is a foundation for the existing engine, not another application or renderer.

`Metal4WindowSurface.h` is a plain C++ header with SDL forward declarations. The engine creates/owns a live **direct SDL3** `SDL_Window` with `SDL_WINDOW_METAL`, initializes SDL3 video and forwards direct SDL3 events. The implementation includes `<SDL3/SDL.h>` directly and uses no SDL2 facade or compatibility window handle. The move-only surface owns one SDL Metal view, layer and retained device. Engine/global window creation, event pumping and controller integration remain HQ-owned. Native Metal4 rendering remains independent of this SDL API migration.

The constructor rejects OpenGL/Vulkan window contexts and duplicate owned surfaces, checks actual Metal4 support and creates the SDL Metal view. Unique ownership uses the window's `SDL_GetWindowProperties` group and a checked pointer property. It configures a BGRA8 layer, explicit display sync/framebuffer-only policy and bounded next-drawable timeout policy, but does not call `nextDrawable`, create a GPU queue, draw or present. The default constructor selects a default device once. The world renderer's shared-device attach factory uses private `AttachWithDevice` to supply its already-selected device and retrieve that same retained device through `Device`; no second device choice is required.

Every creation, observation, event, size setter, native access and detachment/destruction runs on the macOS main thread. The owner must retire all submitted GPU work before `Detach`/destruction, then call `SDL_DestroyWindow`, then shut down SDL video. This object does not wait for or cancel GPU work. It ignores events for other windows and global quit; the engine decides how global shutdown translates into `RequestClose`. Close is sticky and disables presentation eligibility; it does not destroy the borrowed window or remove the view while GPU work might still be using it. Wrong-thread/window-before-surface destruction violates the ownership contract and terminates rather than issuing unsafe AppKit/SDL teardown.

The surface snapshot distinguishes logical SDL window units, actual AppKit presentation/backing pixels and explicitly requested render pixels. The requested render dimensions change only through `SetRenderSize`, bounded to 1–4096 pixels to match the current native asset renderer. Native window resizing, minimize/restore and movement between 1x/2x displays never multiply or replace those render dimensions. Presentation metadata comes from the SDL-owned native view's bounds converted with `convertRectToBacking`, not from `CAMetalLayer.drawableSize`.

The live engine chooses that initial extent after applying its window settings and reading actual logical window geometry. In windowed mode, it uses the complete logical window size after the OS has fitted the requested window to the display; it does not supersample a smaller window using a stale saved height. The complete window includes both viewports in dual-screen mode. Fullscreen retains its separately configured render extent, allowing a selected lower resolution to remain lower than the displayed window. Neither path uses backing pixels. Subsequent resizing and the explicit `SetRenderSize` API retain the surface contract above; initial sizing does not rewrite stored user settings.

SDL3's automatic Metal-view resizing can update layer size on pixel-size events. This surface reasserts exact requested `drawableSize` on `Refresh`, forwarded relevant events and private `Layer` access. It does not mutate global SDL hints. The backing-scale conversion is observation metadata only. The native drawable path obtains the refreshed layer through private access and checks `Snapshot().CanPresent()`; its shared-runtime wait/signal/present sequence is documented in `Metal4WorldRenderer.md`.

Current installed direct headers/library are **SDL3 3.4.18**, verified through pkg-config and `/opt/homebrew/include/SDL3`. The installed SDK is Xcode 27/macOS27. The [SDL3 Metal-view documentation](https://wiki.libsdl.org/SDL3/SDL_Metal_CreateView), [destruction contract](https://wiki.libsdl.org/SDL3/SDL_Metal_DestroyView), [window-properties API](https://wiki.libsdl.org/SDL3/SDL_GetWindowProperties) and [migration guide](https://wiki.libsdl.org/SDL3/README-migration) supplied the direct API contract. The local primary `NSView.h` and `CAMetalLayer.h` supplied exact native signatures. Dedicated `SDL_EVENT_WINDOW_*` types replace SDL2's nested window-event subtype; pixel-size, Metal-view resize and display-scale changes refresh metadata. SDL3 bool size/property results are checked, and visibility is derived from the absence of `SDL_WINDOW_HIDDEN` because `SDL_WINDOW_SHOWN` is removed.

Earlier SDL2 API/`sdl2-compat 2.32.74` window observations and package closure are **historical evidence only**, superseded for the requested direct SDL3 native target. That compatibility library dynamically loaded `libSDL3.dylib` via a Homebrew-relative rpath; it must not become part of the new direct target or an indirect substitute for SDL3 window ownership. The direct target links `SDL3::SDL3`, and HQ owns its new dependency/signing closure and actual loaded-library checks. No compatibility-window run validates the migrated direct SDL3 surface.

The window property group is borrowed, never destroyed by the surface. Construction checks it is valid and has no owner key before creating the view. If a later setup step throws, cleanup removes only this object's pointer property and destroys only its new Metal view; the SDL window/video stay engine-owned. Normal destruction checks main-thread/live-window ordering, removes its owner pointer, clears the layer device and destroys the view. Failure to remove a property during cleanup terminates rather than returning a stale ownership claim. `Detach` is idempotent after detachment and can throw at its main-thread/live-window guards **before** changing state; after valid guards, native cleanup is nonthrowing. It still requires prior GPU retirement. HQ's world bridge separately checks the shared runtime's safe-detachment query before renderer/surface destruction.

Source files are `Metal4SurfaceState.h`, `Metal4WindowSurface.h/.mm`, private `Metal4WindowSurfaceNative.h`, and `Metal4SurfaceStateTests.cpp`. The shared renderer sees Apple types only through the private Objective-C++ bridge. The CPU state reducer is used by the real surface and is tested for 2x backing resize preserving explicit pixels, 2x→1x display changes, explicit resize, no-op observations, invalid setters, minimize/hide/zero backing, restore, sticky close, idempotent detach and detached operations. The test main is enabled only for an explicit test target to avoid accidental inclusion as an engine entry point.
