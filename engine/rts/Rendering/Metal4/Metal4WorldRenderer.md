# Experimental actual-world Metal4 presentation

2026-10-14. Codex assisted this implementation. This source owner performed strict source/header syntax checks only. HQ owns the integrated build, actual MSL compiler, GPU validation, capture and live engine checks. No standalone generated scene or old port source was used.

`Metal4WorldRenderer.h/.mm` consumes the owned immutable `rendering::WorldFrame` produced by the engine's `WorldFrameCapture`. It does not read files, regenerate a camera, change simulation state, draw a minimap in place of terrain, or upload CPU screenshots as a window frame. `AttachMetal4RendererSurface` injects the process-wide `SharedRuntime` device into the borrowed engine SDL window's existing surface abstraction. HQ builds a separate `recoil-metal4-world-renderer` static target linking the existing renderer and surface libraries, so the standalone asset diagnostic need not acquire SDL dependencies and there is still exactly one actual native runtime.

This is a narrow experimental **original diffuse/team terrain + loaded S3O unit scene**. BAR material lighting/PBR/normal maps, water, sky, shadows, features, particles, selection graphics, fonts and general Lua UI remain incomplete. The result reports actual selected-unit flags, without inventing a selection ring or changing their diffuse color. Unsupported source formats remain the CPU capture's reported exclusions.

## Original world resources and current state

The static terrain cache retains the `shared_ptr<const WorldTerrainTiles>` identity, original z-major tile-index grid and unique SMT bytes. Each original 32×32 BC1 tile retains all four mips (32/16/8/4 texels; offsets 0/512/640/672; 680 bytes total). Texture arrays are partitioned into at most 2048 layers. No recompression, minimap sampling or tile substitution occurs. This first native path explicitly requires BC texture support; it fails if absent.

One cached tile-instance buffer per array partition records grid x/z and original slice. Its vertex shader emits the full sixteen heightmap cells inside each tile. Each corner reads the actual current unsynced height buffer at z×width+x and retains the real engine square size. The triangle diagonal/order follows the pinned full-detail `BasicMeshDrawer` → `RenderBuffers.h::MakeQuadsTriangles` algorithm (tl/bl/tr, tr/bl/br). It does not claim the adaptive ROAM/LOD implementation. Original SMT rows increase map z and are sampled directly; unit DDS V inversion is separate.

Each array-slice upload uses block-aligned full-mip regions and BC1 block-row strides (64/32/16/8 bytes). The 4×4 final mip is exactly one 8-byte BC1 block. `bytesPerImage` is zero because the destination is a 2D array rather than a 3D texture, as required by [Apple's texture upload contract](https://developer.apple.com/documentation/metal/mtltexture/replace(region:mipmaplevel:slice:withbytes:bytesperrow:bytesperimage:)). This argument was corrected during the read-only API audit, before GPU execution. [Apple's array-length contract](https://developer.apple.com/documentation/metal/mtltexture/arraylength) specifies 1–2048 layers inclusive; a stale SDK descriptor comment stating “less than 2048” does not change that documented inclusive maximum.

Jade's supplied real map is 2048×2048 squares, with 4,198,401 corner values and 262,144 original unique SMT tiles. Its BC1 payload is approximately 178 MB and uses 128 array partitions. This first path has no terrain LOD/frustum optimization and submits every full-detail tile. Performance optimization and seam-equivalence checks remain necessary; successful API execution does not establish game frame rate or Linux visual parity.

Loaded model caches retain exact piece-local `WorldModelVertex` bits, both UV channels, normals/tangents, four bone IDs/weights and original local triangle indices. Static assertions check the 76-byte vertex layout and offsets. The initial shader uses position and UV0 and requires the actual postprocessed S3O convention: first bone ID equals preorder piece index, first weight 255, other weights 0. It rejects multi-bone/weighted input rather than silently treating it as a rigid piece. Current unit world and current piece model-space matrices are copied into per-frame uniforms; bind/rest matrices do not replace live pose state. Invisible pieces are omitted, including genuine script visibility state.

Unit textures are loaded by the engine CPU capture, with all supplied mip bytes, exact format and explicit `flipV`. The native backend only uploads those owned bytes. The fragment shader uses original tex1 RGB/team-alpha mixing and writes raw original tex2 alpha, but the unit pipeline is **opaque and writes depth**. Raw alpha output is not continuous-alpha compositing: alpha-zero texels can still overwrite color and occlude later geometry. Transparent/cutout units and material-pass specialization are explicitly unsupported. The frame lacks actual `HASALPHASHADOWS`, transparency/sort/pass state; applying a universal cutoff or generic blend would invent unavailable engine material behavior. Full alpha rendering needs that real material contract alongside the missing modern BAR material stack.

Static map, model and texture resources persist across completed frames. Ordinary per-frame corner heights, camera and unit piece poses update without asset decode, file I/O or image readback. Diagnostic bounds currently allow terrain dimensions through 8192 squares, 1 million unique tiles, 2 million vertices/12 million indices per model, 100,000 visible pieces, 256 cached models and 512 cached texture resources. These are explicit implementation/allocation bounds, not advertised game-product limits. Surface render pixels still use the existing explicit 1–4096 diagnostic cap; future ultrawide/5k settings need device-based validation.

## Camera, extent and native submission

Camera view/projection matrices remain the engine's column-major matrices. `ClipDepthConvention::MinusOneToOne` converts only clip z using `(z+w)/2`; `ZeroToOne` passes through unchanged; unsupported convention fails. No new camera or camera aspect is generated. Logical SDL/picking viewport and explicitly requested render pixels remain distinct. The actual bottom-left logical camera subview maps proportionally to the raster target: x×renderWidth/logicalWidth; top y=(logicalHeight−y−height)×renderHeight/logicalHeight; width/height scale by the corresponding render/logical ratio. Only the resulting scissor is clamped; the viewport/projection remain intact. Returned `renderViewport` metadata makes this mapping explicit. Fully offscreen views skip; mapped viewport values beyond the experimental ±16,384 numeric bounds fail before submission. A surface resize refreshes logical/backing metadata while preserving the owner's explicit render dimensions. Backing pixels never enter viewport mapping and there is no implicit Retina multiplication.

Presentation is main-thread-only. A frame distinguishes detached, close requested, hidden, minimized, zero display extent and unavailable drawable from an actual native presentation. Resource uploads/shader setup happen before acquiring `CAMetalLayer.nextDrawable`. The drawable texture must match the explicit requested render size. Ordinary frames perform no target readback.

`RuntimeLease::SubmitAndWait` has an optional drawable parameter; existing asset/screen callers default to nil and retain their prior behavior. For presentation it queues `waitForDrawable` before commit, then `signalDrawable` after commit, then `drawable.present`. It schedules the monotonically increasing shared completion event and waits for both that event and commit feedback before resetting command memory. The drawable and every submitted resource are retained in the immutable completion graph, including when a timeout causes a late callback. The existing unsafe-lease poisoning rule prevents command-memory/resource reuse after an unsafe failure.

The owner creates the borrowed SDL window, attaches the shared-device surface, creates this renderer, and forwards events through the engine event loop. After successful synchronous draws have retired, destroy the renderer, detach/destroy the surface, then destroy the SDL window and SDL video. After a thrown error, the owner must query `Metal4RendererCanSafelyDetachSurface()` before normal teardown. Shader/setup failures and recording-only failures have no unretired submitted work; a GPU error whose event and feedback both completed can also tear down safely, although native command reuse remains poisoned. A timeout leaves unsafe pending work and permanently returns false until process restart, even if feedback eventually arrives. The world renderer destructor terminates on this unsafe condition so normal C++ cleanup cannot silently release live native resources. `Presented` means scheduled using Metal's drawable presentation contract and GPU submission retired; it does not measure physical display scanout.

Apple primary API references supporting this ordering:

- [Metal4 waitForDrawable](https://developer.apple.com/documentation/metal/mtl4commandqueue/waitfordrawable(_:))
- [Metal4 signalDrawable](https://developer.apple.com/documentation/metal/mtl4commandqueue/signaldrawable(_:))
- [Drawing a triangle with Metal4](https://developer.apple.com/documentation/metal/drawing-a-triangle-with-metal-4)

The installed SDK `MTL4CommandQueue.h` independently documents wait-before-commit and signal-after-commit-before-present. No legacy command queue/encoder or translation fallback is introduced.

## Explicit drawable readback

`Metal4WorldRenderOptions::readbackRGBA` defaults to false. An explicit request requires `Metal4SurfaceConfig::framebufferOnly=false` when attaching the surface; requesting a copy from a framebuffer-only layer fails before command recording. The existing render pass still draws the exact current `WorldFrame` to its actual drawable. No second camera, offscreen re-render, CPU image presentation or OS screen permission is involved.

For that requested frame only, a shared destination buffer is allocated with a conservatively aligned 256-byte row pitch and added to the same residency/strong completion graph before command recording. After the render encoder stores the drawable and ends, a direct `MTL4ComputeCommandEncoder` issues a consumer queue barrier from prior `MTLStageFragment` work to this encoder's `MTLStageBlit` work, with device visibility, followed immediately by texture-to-buffer copy. Source slice/level/origin are zero, the region is the exact drawable width/height/depth 1, and `destinationBytesPerImage` is zero. The existing wait/commit/signal/present path retires both the render and copy through the same event and commit feedback. CPU buffer contents are read only after successful retirement. There is no `getBytes` call on the private drawable.

The installed SDK's `MTL4ComputeCommandEncoder.h` and [Apple's texture-to-buffer copy contract](https://developer.apple.com/documentation/metal/mtl4computecommandencoder/copyfromtexture:sourceslice:sourcelevel:sourceorigin:sourcesize:tobuffer:destinationoffset:destinationbytesperrow:destinationbytesperimage:) specify copyability and row/image stride requirements. The consumer barrier follows `MTL4CommandEncoder.h` and [Apple's Metal4 combined copy/compute pass guidance](https://developer.apple.com/documentation/metal/combining-blit-and-compute-operations-in-a-single-pass). It synchronizes prior encoders; an intra-encoder barrier would not express this render-to-copy dependency.

On success, `rgba` is tightly packed top-down RGBA8; `readbackWidth` and `readbackHeight` are the actual source dimensions. Packing removes buffer row padding and swaps raw BGRA B/R bytes without flipping rows, changing alpha or re-encoding color. `readbackSRGB` marks an sRGB drawable encoding and `readbackOpaqueLayer` records the layer's opacity. This is exact drawable texture data rather than an OS compositor screenshot: an opaque layer can display stored alpha as opaque, while an RGBA PNG viewer may use that alpha. The caller owns its PNG representation and must document any deliberate alpha omission. Unsupported source formats fail; the current native surface uses BGRA8 or BGRA8 sRGB.

`readbackMs` (also `FrameMetrics::cpuReadbackMs`) measures only the CPU allocation/packing/swizzle after GPU retirement. The frame's GPU execution and command preparation scopes include the requested copy; they must not be compared to ordinary presentation without identifying that extra work. `copyEncoderClass` records the actual native class. Skipped frames return an empty pixel vector and zero readback dimensions, and ordinary requests incur no readback allocation, encoding or CPU copy.

## Verification handoff

Strict checks passed using the selected installed SDK:

```sh
xcrun clang++ -std=c++23 -fobjc-arc -fblocks -mmacosx-version-min=26.0 -arch arm64 -fsyntax-only -Wall -Wextra -Wconversion -Werror rts/Rendering/Metal4/Metal4WorldRenderer.mm rts/Rendering/Metal4/Metal4RuntimeNative.mm
xcrun clang++ -std=c++23 -x c++ -fsyntax-only -Wall -Wextra -Wconversion -Werror -include rts/Rendering/Metal4/Metal4WorldRenderer.h /dev/null
xcrun clang++ -std=c++23 -fsyntax-only -Wall -Wextra -Wconversion -Werror -DMETAL4_WORLD_VIEWPORT_TEST_MAIN rts/Rendering/Metal4/Metal4WorldViewportTests.cpp
```

The guarded pure-CPU `Metal4WorldViewportTests.cpp` main uses `METAL4_WORLD_VIEWPORT_TEST_MAIN` and needs no native libraries. Its 15 analytic checks cover an independent square target, subviews, bottom-left y mapping, negative/unmodified viewports with clamped scissors, right/top overflow, fully offscreen views, signed endpoint extremes, fractional pixel coverage and rejected empty extents. HQ owns execution.

These source checks do **not** compile the embedded MSL. HQ must run the actual engine WorldFrame path with `MTL_DEBUG_LAYER=1 MTL_SHADER_VALIDATION=1`, recording real shader compile/submission feedback and presentation status. A separate fresh GPU capture uses `METAL_CAPTURE_ENABLED=1`, shader validation disabled in both environment and per-pipeline option. Capture and shader validation are intentionally separate on the observed host.

HQ's direct SDL3 scene run 01 reported first original Jade terrain presentation at 38.3 seconds, then a current commander at frame 95/40.9 seconds: 1 unit, 19 visible pieces, selected-unit flag 1, using the actual Metal4 debug queue/buffer/encoder. HQ subsequently reported runs 01 and 02 both completed their bounded 90-second sessions cleanly with API and shader validation, presenting original terrain and current commander. These runs preceded the optional GPU readback addition. OS capture of the owned window failed with “could not create image from window”; that failure motivated the explicit same-drawable copy above. HQ run 03 subsequently passed the actual same-drawable copy with API/shader validation. It saved frame 151 at 1280×720 using MTL4DebugComputeCommandEncoder, recorded 352 presented frames through simulation frame 1122, and exited cleanly after the 75-second limit. HQ inspected the PNG: the original near-corner terrain and small commander are visible; original UI is absent. The PNG omits alpha to match the actual opaque layer, while the renderer retains raw RGBA. These observations validate this bounded copy/presentation path, not full graphics or interaction. The source owner performed no GPU invocation. None of this establishes Linux visual parity, complete materials/UI, input acceptance or game frame rate.

Acceptance must retain actual CPU map/unit/camera data evidence, successful original terrain/model shader compilation, the direct queue/buffer/encoder class labels, stable static resource identities across frames, current piece/move changes, close/minimize/resize handling and unchanged requested pixels on backing-scale changes.

The world subset draws original model geometry at all captured distances. Native unit-icon presentation is not implemented. The ordinary engine/Lua selection state remains authoritative, including the BAR Ignore Self widget temporarily reducing the currently selected unit’s selection volume and restoring it on a real left mouse press. Diagnostics must not infer that a pre-click trace miss means the actual click path cannot select the unit.
