# Private Sepia shared-program pilot

The default selects the original Sepia MSL shader and legacy output packing, with the pilot’s new Lua linking/material capture front end shared by both modes. This is an old-shader/shared-shader comparator, not the unchanged deployed production path. `BAR_METAL4_SEPIA_PATH=shared` selects the same baseline effect through the generated program and immutable shared records. No game or GPU parity/performance result is claimed here.

`sepia.vert.glsl` and `sepia.frag.glsl` are exact runtime strings extracted from Beherith's current widget (GPL v2 or later); Lua removes the initial newline of a long string. Their FNV hashes match the frozen old adapter: 16905188423406352921 and 17382421314025316268. See PROVENANCE.json for the verified current baseline pool object and complete widget hashes.

Run `python3 tools/sepia-pilot/compile_subset.py` from the engine tree to regenerate the C++ admission/header, JSON layout, MSL, and `data/LuaUI/NativeWidgets/sepia_pilot_program.lua`. `--check` verifies reproducibility. A custom `--fragment` and `--output` produces isolated variant outputs. There is no installed general GLSL compiler in the checked locations; this implementation is a deterministic typed-expression AST subset compiler, with explicit fail-closed rejection. It pins the full-screen vertex transport and actually parses/translates fragment expressions, locals, typed uniforms/defaults, constructors, swizzles and supported functions. Its only texture intrinsic preserves the original lod-zero screen-copy coordinate expression. Unsupported stages, operations, types and texture addressing fail. The generated MSL asserts block size and all field offsets.

The variant in `checks/sepia/variant` adds float `exposure=1.25`, vec3 `bias=vec3(0.1,0.2,0.3)` and evaluates `pow(...) * exposure + bias`. It moves gamma's offset and increases the block from 128 to 160 bytes. The actual generic C++ payload implementation compiles and accepts both new fields without a production C++ change. Actual Lua adapter execution with the variant's generated module forwards both new uniforms. Both sample modes pass Metal syntax including generated layout assertions. These are bounded host/compiler checks; the Lua binding is mocked in the host Lua check, and no actual Lua engine or renderer is launched.

## Connected path and ownership

The existing engine native-widget loader selects `LuaUI/NativeWidgets/gfx_sepia_tone.lua`; its exact updated wrapper SHA512 is included in this overlay’s rts/Lua/NativeWidgetAdapters.h. `LuaNativePostprocess.cpp` registers NativeSepiaLoadSource (archive ZIP read) and NativeSepiaContext (this changed native context). It has no additional whole-widget hash gate. The wrapper's fixed archive-widget hash remains strict for old mode; shared mode admits the generated source module instead, and NativeSepiaLuaContext compares its exact vertex/fragment strings against the generated linked program. A changed supported archive widget is therefore not rejected by the old whole-widget gate before shared stage admission.

Generic SetUniform/SetUniformInt validate generated types/dimensions and publish immutable byte owners at updates. Draw retains the linked interface generation, uniform owner and the actual observed unit0 postprocess version in MaterialContent. Program deletion/relink and consumer reset invalidate future use. Already captured owners retain the actual successful MTLLibrary, not an integer admission marker. ProgramInterface block slot1, generated field blockSlot1, MSL buffer(1), the existing two-buffer argument descriptor and C++ setAddress index1 agree; texture0 stays a direct texture slot.

Recorder and operation validation retain the snapshot and compare the exact captured input version. Shared Prepare constructs a PreparedSlice, copies generated user bytes without field names, patches only per-use target/alpha/depth transport, and uses the existing uniform pool, ImageFor resolver, read receipts, argument lifetime, raster helper and selected pipeline. Source order, attachments and completion ownership remain the original path. Old direct NativeSepiaUniforms callers may omit the new material; legacy fields and original aggregate order are preserved. Sepia introduces no cross-frame binding cache or cached readability verdict.

## Bounded verification

- Four Python tests cover exact stages/reproducibility, equation plus added float/vec3/default/layout changes, reordering, and unsupported-input rejection.
- Actual C++ header payload tests pass ownership, relink, deletion, reset, immutable updates, wrong scalar/count/range and changed input-owner cases, against the final common header.
- Host Lua adapter test passes generated source selection, edited-widget shared admission, strict old rejection, uniform forwarding, linked draw forwarding and deletion guards. It uses a mock native binding.
- Baseline and variant old/shared combined MSL pass `xcrun metal -std=metal4.0 -fsyntax-only`, with sample shading both disabled and enabled; generated layout assertions pass.
- Existing production TestNativePostprocessPlan fixture passes 38 checks under ASan/UBSan, linked to actual changed data implementation using the coordinator's VFS overlay. The frozen NativeWorldFontGeometry.h has an existing misleading-indentation warning; that one warning was kept visible and removed from Werror for this host fixture.

The engine data directory here is an unapplied packaging overlay. A future private build owner must install both Lua files into the private app's native-engine data tree and apply the engine overlay, including the supplied loader hash change. No installed app, release, repository, frozen source, K candidate or performance candidate was changed. Full engine build, real Lua/native execution, rendered old/shared parity, readiness/order adversarial GPU checks and performance measurement remain unverified.
