# Seths cap2의 Grass 픽셀 차이와 지형 재질 읽기 생략

## Grass

단일 프레임에서 매번 같은 색상·깊이·스텐실로 시작해 OFF와 ON을 각 8회 그렸다. 같은 모드끼리도, 서로 다른 모드끼리도 비교했다. 아래의 고정 차이는 한 모드의 8회 결과가 모두 같고 반대 모드 8회와는 다른 픽셀 수다.

| 기능 | 장면 | 색상 BGRA8 | 깊이 D32 | 스텐실 S8 |
|---|---|---:|---:|---:|
| 풀을 휘게 하는 유닛의 후보 목록 축소 | 600틱, 실제 유닛 접촉 | 0 | 0 | 0 |
| 크기 0인 풀 제거와 남은 인스턴스 압축 | 1665틱, 21,504개 중 304개 렌더 | 34 | 2 | 0 |

후보 축소에서 이전에 고정돼 보이던 색상 네 좌표와 깊이 한 좌표는 새 16회 전부에서 일치했다. 당시 입력을 역투영했을 때 네 좌표 모두 영향을 준 유닛이 0개인 Grass 드로우에 속했다. 이번에 한 번이라도 값이 달라진 색상 픽셀은 62개, 깊이는 1개였고, 각각 OFF와 ON에서 적어도 한 번은 같은 값이 관측됐다. [후보 축소 16회](grass/bending/BALANCED-RESULTS.json) · [기존 픽셀 위치와 유닛 영향 대조](grass/BEND-PIXEL-WORLD-LOCATION.json)

크기 0 압축에서는 두 깊이 픽셀 모두 OFF·ON에서 풀이 그려졌지만 깊이 값이 각각 267·27 ULP 달랐다. 같은 위치의 알파 값은 각각 237→201, 238→221이었다. 기존 4회 대조에서 고정돼 보였던 색상 20좌표는 새 프레임에서 모두 일치했다. 같은 틱이라도 별도로 시작한 게임에서 차이의 좌표는 옮겨갈 수 있다. [압축 16회](grass/compaction/BALANCED-RESULTS.json)

1665틱의 다른 고정 프레임에서 8가지 배치를 각 4회 비교했다. 색상 차이가 반복된 15픽셀 모두 원래 배열의 바이트를 새 버퍼로 복사하거나 맨 뒤의 크기 0 항목만 잘라내면 원래 결과를 냈다. 드로우 개수·시작 인덱스·인스턴스 수를 유지하고 살아 있는 풀을 앞쪽 슬롯에 모은 경우에는 15개 모두 압축판 결과를 냈다. 살아 있는 풀의 드로우 내 배치가 색상 차이를 유발한다. GPU 내부의 정점 처리, 래스터화, 보간 중 최초로 값이 갈리는 단계는 이 검사에서 구분할 수 없다. 이 32회 프레임에서는 깊이 고정 차이가 재현되지 않았다. [배치별 원자료](grass/factors/FACTOR-RESULTS.json)

GroundFlash·Distortion·GroundDecal 냉각 감쇠는 동일 입력 1665틱의 색상·깊이·스텐실 차이가 모두 0이었다. Distortion 누적 버퍼도 일치했다. GroundDecal flat-wrap과 큐브맵 재사용의 검증 자료는 개별 GPU 대조이고, Lua Nano는 합본 실제 장면의 같은 입력 픽셀 대조를 확인하지 못했다. [검증 범위](ground-track-pixel-inventory.json)

## 지형의 네 상세 재질 읽기

Seths cap2, AC 자동, 1512×950 Ultra AA0. 합본 바이너리에서 Grass 후보 축소·GroundDecal flat-wrap·큐브맵·Lua Nano 4종 ON. 아래는 마스크 출력을 끈 일반 셰이더에서 측정한 GPU 프래그먼트 시간이다.

| 시뮬레이션 틱 | G-buffer OFF → ON (ms) | 주 화면 forward OFF → ON (ms) | 공통 두 패스 합 OFF → ON (ms) | 변화 |
|---|---:|---:|---:|---:|
| 1200 | 0.259707 → 0.297580 | 0.975687 → 0.989333 | 1.235394 → 1.286913 | +4.17% |
| 1590 | 0.259872 → 0.300648 | 0.978667 → 0.981333 | 1.238539 → 1.281981 | +3.51% |

별도 마스크 캡처에서 1200틱 화면에 남은 1,436,400개 지형 픽셀 × 4채널 중 가중치가 정확히 0인 슬롯은 847,711개(14.75%)였다. 주변 네 픽셀 조건까지 통과한 슬롯은 794,636개(13.83%)였고, 4번 재질에 618,353개가 몰렸다. 3번 재질은 0개였다. 1590틱은 각각 847,710개와 794,631개였다. 이 수치는 앞의 G-buffer 픽셀을 대상으로 하며 물리적 GPU 메모리 접근 횟수는 측정하지 않았다. [마스크와 GPU 시간](terrain/TERRAIN-RESULT.json) · [캡처된 재질·셰이더 대조](terrain/MATERIAL-PROVENANCE.json)

기본 셰이더는 네 상세 재질을 읽을 좌표가 가중치와 독립적이다. 스킵을 켜면 각 상세 재질을 읽기 전에 가중치 텍스처 결과와 네 픽셀의 마스크 결합이 필요하다. 네 읽기 중 86% 이상이 남고, 가중합과 정규화도 그대로 실행된다. 실제 GPU에서는 G-buffer가 두 틱 모두 약 0.04ms 길어졌다. 현재 증거로는 가중치 판정·분기·읽기 대기 각각이 차지한 시간을 분리할 수 없다. [컴파일된 의존 관계](terrain/AIR-DEPENDENCIES.json)

두 팔의 틱·카메라·유닛 수는 같았고 두 주 패스는 각각 14드로우였다. 제출 인덱스 수는 OFF 259,695, ON 259,977로 0.109% 달랐다. 1200틱은 ON 쪽에만 지형 반사가 있어 양쪽에 존재한 두 주 패스를 비교했다. 이런 별도 실행 간의 출력 차이만으로 지형 셰이더의 픽셀 동등성을 판정할 수 없다.

이전 네 기능 ON 기준의 실게임 전체 프레임에서 지형 OFF는 평균 90.06 FPS·1% low 61.56, 지형 ON은 89.22·53.18이었다. 18ms 이상 프레임은 OFF 1개, ON 18개였고 ON의 17개는 1410~1590틱에 있었다. 두 틱의 셰이더 시간만으로 그 17개 프레임의 지연 원인을 분해할 수 없다. [프레임별 집계](TERRAIN-FRAME-TAIL.json)
