# Native 220의 직전 제출 대기 분해

기존 잠금 해제 진단의 Native 수집 ON 실행을 다시 읽었다. 게임 재실행과 빌드는 없었다. 원본은 비교 묶음의 [GPU 트레이스](original/gpu/native-budget192.csv.gz)이며 압축을 풀었을 때 SHA-256은 `88fb94eb5b01ca9d9c405dc7dd66774641f0a32ef571d1f9a5aa64820e07cf40`이다.

트레이스의 6,388개 제출 레코드 그룹 모두 제출 범위 20, 선행 이벤트·피드백 대기 21, GPU 커밋 10, 완료 소유자 해제 23 순이었다. 각 그룹의 21을 직전 그룹의 10과 연결했다. 행의 완료 플래그, 오류, 스레드 일치와 타임스탬프 순서를 검증했다. 원래 시뮬레이션 600–1800 구간의 양끝 100ms를 잘라내고 대기 구간 전체가 그 안에 들어온 6,357개만 집계했다. GPU 종료 후 피드백이 대기와 겹치는 길이는 `max(0, min(wait.end, previous.callback) - max(wait.begin, previous.gpu_end))`이다.

| 구간 | 평균 | 중앙값 | p99 |
| --- | ---: | ---: | ---: |
| 이벤트와 피드백을 합한 실제 대기 | 0.0510ms | 0.0006ms | 0.7657ms |
| GPU 종료 → 피드백 콜백 시각 | 0.1463ms | 0.1437ms | 0.2498ms |
| GPU 종료 후 콜백까지의 구간 중 실제 대기와 겹친 부분 | 0.0162ms | 0ms | 0.1679ms |
| GPU가 끝나기 전에 기다린 부분 | 0.0332ms | 0ms | 0.5975ms |

GPU 종료 이후 콜백까지의 지연이 대기와 겹친 경우는 810/6,357개였다. 이 장면에서 피드백으로 인한 지연이 매 프레임 그대로 노출된다는 가설과는 맞지 않는다. 콜백과 이벤트의 순서가 다를 수 있으므로 0.0162ms는 콜백을 기다리면서 없앨 수 있는 시간의 측정값이 아니라 겹친 시간이다. 대기 밖의 준비나 엔진의 선행 프레임 완료 의존성을 포함한 새 제출 구조의 이득도 이 자료에서 추산할 수 없다. GPU 제출 깊이 2의 효과를 보려면 슬롯과 소유권을 분리한 별도 A/B에서 제출·표시 지연과 프레임 간격을 함께 비교해야 한다.
